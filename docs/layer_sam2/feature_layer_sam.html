Feature Layer-SAM

Layer-SAM helps a frozen SAM2 see a person behind foliage by combining the last few frames. This page explains how to do the same at real-time speed: combine the frames after encoding them, not before.

Idea 1

Reuse features instead of re-encoding

Each past frame was already encoded when it was the current frame, so its SAM2 features \(K_k\) are in memory. After shifting them so the person lines up, a small network decides, for each location, how much to trust each past frame, or to fall back to the empty scene \(B\):

\[ \hat C = \sum_{k=1}^{6} \alpha_k\, K_k \;+\; \alpha_\varnothing\, B, \qquad \textstyle\sum \alpha = 1 . \]

This saves the second encoder pass: about 39 ms per frame instead of 62.

Idea 2

A weighted average is not enough

When a person is only ever seen in fragments, every past feature describes "leaves plus a fragment". An average of such features is still "leaves plus a fragment". Encoding the averaged image can produce "person", because the encoder sees all the fragments at once. That is a combination no weighted average can reach:

\[ E\Big(\sum_k w_k\, X_k\Big) \;\neq\; \sum_k w_k\, E(X_k). \]

So at the coarsest scale the average is replaced by a small nonlinear network \(N\) that sees all past features unmixed:

\[ \hat C = N\big(K_1, \dots, K_6,\, F_t,\, B\big). \]

It predicts the features of the averaged image well on real footage it never saw (cosine 0.85, against 0.79 for the best average), at under 1 ms per frame.

Idea 3

Train it through the reader that already works

Matching the pixel model's features is not enough. The adapter has to use them, and an adapter retrained on synthetic data ignores them on real footage. The pixel model's adapter \(f\) is the one reader known to use the integral on real data. So we keep \(f\) frozen and train the feature integral so that \(f\) responds to it as it responds to the real thing:

\[ \min_{\hat C} \; \mathcal{L}\Big( f(\hat C),\; f\big(E(C)\big) \Big). \]

This needs no labels: any real video from a static camera is training data.

Extension

A moving scene: learn the empty scene too

Today the empty scene \(B\) is a median of the first frames, encoded once. That assumes a static camera and steady light. The same module can estimate it. It is another learned combination of cached features, with different weights \(\beta\) that pick, at each location, the past frames where the person was not there:

\[ \hat B_t = \sum_{k} \beta_k\, \tilde K_k . \]

Two changes from \(\hat C\):

  • The past features \(\tilde K_k\) are aligned to the camera, not to the person.
  • The history is longer, because background must be seen with the person elsewhere.

It even comes with free supervision. Away from the person, the current frame is the background, so \(\hat B_t\) can be trained to predict \(F_t\) outside the tracker box, on any video. This is not needed for NFO or camera traps, where the camera is fixed. It is the route to a moving camera, which would also need full 2-D alignment.
